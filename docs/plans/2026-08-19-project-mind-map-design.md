# 项目思维导图设计

## 目标

在项目内部补齐真正的思维导图视图。它用于从项目主题出发分层拆解方向、里程碑、执行路径和想法，并允许主题节点关联任务、工作树、里程碑与知识实体。

## 与其他视图的分工

- 白板（首版暂缓）：自由摆放问题、证据和临时材料，空间关系优先。
- 思维导图：围绕一个中心主题进行父子层级拆解，结构和思路优先。
- 3D 知识图谱：跨项目浏览双向链接和网络关系，全局关系优先。

## 交互方案

采用“树状画布 + 实体详情面板”的组合。画布以 PixelMind 为中心，一级主题覆盖产品方向、里程碑、执行路径和想法池，二级主题连接具体任务、工作树、验收标准与 Agent 能力。

- 点击节点：选中并在右侧显示类型、状态、负责人、实体链接和反向链接。
- 折叠/展开：有子主题的节点显示折叠控制，隐藏或恢复全部后代。
- 新增子主题：以当前节点为父级创建新想法，自动建立父子边。
- 编辑主题：在详情面板直接修改主题名称，画布同步更新。
- 关联实体：把当前主题关联到工作树、任务或里程碑，并给出写入反馈。
- Agent 整理：触发 Agent 对当前分支的归类建议，并写入项目日志反馈。
- 适配视图：恢复自动缩放，使全部可见主题进入画布。

## 数据模型

每个主题节点包含 `id`、`parentId`、`kind`、`label`、`meta`、`status`、`owner`、`entity`、`backlinks`、`side` 与画布坐标。边表示父子结构；`entity` 和 `backlinks` 表示知识层的双向关系。折叠状态独立维护，避免破坏节点本身的数据。

## 异常与边界

- 未选中节点时默认选择项目根主题。
- 根主题不可被折叠到不可见状态。
- 新增节点时根据父级方向放置，避免覆盖当前节点。
- 窄屏隐藏详情面板，保留画布与核心工具；详情信息可通过后续抽屉形态扩展。

## 验收

- 页面标题明确为“项目思维导图”，与知识图谱区分。
- 父子层级、折叠展开、选择、编辑、新增子主题和实体关联均可操作。
- 桌面、平板和窄屏下没有文档级横向溢出。
- 浏览器控制台无 error、warning 或 issue；构建和 Sites 测试通过。
